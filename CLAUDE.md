# BusMate — agent operating instructions

This repository is developed under **HACO** (Human-Governed AI Co-Development). The full methodology
is [haco-methodology.md](haco-methodology.md); this file is the operating summary. It supersedes any
earlier agent guidance found elsewhere in the repo.

## Read these first

| File | Why |
|---|---|
| [intent/context.md](intent/context.md) | Architecture, stack, invariants, conventions, known debt. **Read before any task.** |
| [intent/policy.yaml](intent/policy.yaml) | Risk class and permitted autonomy for the paths you are about to touch |

## The three planes

Every project fact lives in exactly one place. **A plane must never restate a fact another plane
owns** — duplicated truth becomes contradictory truth, and you will not know which copy is lying.

| Plane | Owns | Where |
|---|---|---|
| **Intent** | *Why* and *what* — goals, constraints, acceptance criteria, decisions | `intent/` |
| **Code** | *Behaviour* — what the system actually does | `apps/`, `libs/`, `tests/` |
| **Evidence** | *What happened* — history, results, outcomes | git, CI, PR threads. **Never a file.** |

So: never write a changed-file list, a test count, a status field, an approver name, or an API
endpoint path into `intent/`. `git diff`, CI, the PR, and the code already own those. The test for
Intent-plane content is: *if I deleted this sentence, would the information be unrecoverable?*

## Before you change code

1. **Find the risk class** of every path in the diff from `intent/policy.yaml`. A change spanning
   multiple classes takes the **highest** one.
2. **Check `always_human`.** If the change is on that list, stop and ask — regardless of risk class.
3. **Pick the track** by blast radius, not by effort:
   - **Track 0** — reversible, no risky surface, obvious. No increment file. `Increment: none`.
   - **Track 1** — most feature work. One file in `intent/increments/`.
   - **Track 2** — auth, money, personal data, migrations, published contracts, or anything hard to
     reverse. Increment file + design + ADR + a named reviewer.
4. **Set autonomy honestly.** Above A2 is earned by tests that would catch the failure, never by
   confidence. If the honest answer to *"what would catch this if it were wrong?"* is "a human
   reading carefully", it is A2 — whatever the policy table permits.

## Anchors — how intent connects to code

- Branch name contains the increment ID: `inc-014-live-tracking`
- **Every commit carries an `Increment:` trailer** — enforced by
  [.githooks/commit-msg](.githooks/commit-msg). Use `Increment: none` for Track 0.
- Acceptance-criteria tests name the increment ID in their test name.
- Code comments carry the ID **only where intent is non-obvious** from the code — a magic number, a
  workaround, a deliberate deviation. Not everywhere; comment spam is its own decay.

This makes traceability a git query (`git log --grep='Increment: INC-014'`) that cannot rot. Never
build or maintain a traceability table.

## Increment files

One file per increment in `intent/increments/`, named `INC-nnn-short-slug.md`:

```markdown
---
id: INC-014
title: Live vehicle tracking on route detail
state: active          # proposed | shaped | active | in-review | done | parked | dropped
track: 1
risk: R2
owner: kavinda         # the accountable human. Always a person, never a team or an agent.
autonomy: A2
---

## Goal
[One or two sentences. Observable value.]

## Why now

## Acceptance criteria
- [ ] [Stated in observable terms — what a person could check.]

## Out of scope

## Constraints

## Open questions

## Decisions
- See ADR-nnn
```

Nothing else. No subtask status, no file list, no test counts, no timestamps, no "generated by AI"
metadata — git owns all of it.

**Sizing:** if an increment cannot be reviewed by one person in under an hour, it is not an increment,
it is a project. Split it. This is the main mechanism keeping human review ahead of AI output volume.

## Working agreements

- **Do not create intent files speculatively.** Create one when a specific piece of work needs it.
  A structure filled in dutifully and read by nobody is the failure mode this methodology exists to
  prevent.
- **Update `intent/context.md` the same day an architectural fact stops being true.** A stale context
  file misleads every agent that reads it.
- **Never edit an accepted ADR.** Supersede it with a new one that links back.
- **A human finishing what an agent started is normal**, not a failure. Record nothing special.
- **Do not maintain notes outside `intent/`.** One shared state, no exceptions.
